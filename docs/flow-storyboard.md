# Storyboard flow — presenter / podcast explainers

The flow for videos carried by a **speaking person generated by the video model** (a host to
camera, a podcast host, a guest), with every other element built in Remotion and laid over,
beside or under them. It is how HeyAnaya Script 3 was made. The person is the only thing the
generator makes; the voice is his own, lip-synced, so there is no separate VO track.

```
 script.md + brand + cast still
    │
 ① STORYBOARD ─────── storyboarder designs the video from the script     → 02_storyboard/
    │                  clips · views · Flow/Runway prompts · per-beat
    │                  host layout · an original graphic for every beat,
    │                  each element cued to a spoken word
    │  (gate 🔍: user approves storyboard.md)
 ② GENERATE ───────── user pastes each prompt into the generator          → 04_clips/
    │                  (runway profile: the API may generate instead)
 ③ INGEST ─────────── tools/ingest.py: transcribe, match takes to clips,   → 05_ingest/
    │                  crop bars, trim to speech, clean audio, words
    │  (check: every clip matched, similarity ≥ 0.8, nothing cut mid-word)
 ④ SCENES ─────────── scene-builder writes each storyboard scene as a     → remotion/src/projects/<slug>/
    │                  Remotion component for THIS video
 ⑤ EDIT + QC ──────── tools/build-timeline.mjs → tools/stills.sh →        → 06_edit/ 05_review/stills/
    │                  look at every sheet, fix, repeat
    │  (gate 🔍: user approves the stills or a draft render)
 ⑥ RENDER ─────────── tools/render.sh: both aspects, mastered, versioned  → renders/
    (loop: watch → diagnose → fix the storyboard or a scene → v02…)
```

`state.json`: `"flow": "storyboard"`, `stage` ∈ `storyboard | generate | ingest | scenes | edit | render | done`.

---

## ① Storyboard

**Agent:** `storyboarder` · **In:** `00_script/script.md`, `01_vision/vision-board.json` (cast
descriptors, brand, palette, generator), `01_vision/refs/` (the cast still), and the user's notes ·
**Out:** `02_storyboard/storyboard.json`, `02_storyboard/storyboard.md`, `03_prompts/clip-NN.prompt.md`

The storyboard is designed, not filled in. Read the script as a director: what does the viewer
need to *see* while each sentence is said? A reference of the quality bar is in
[examples/heyanaya-script3](examples/heyanaya-script3/) — study it, do not copy it. A new script
gets its own visual ideas.

### 1. Split the script into clips

- One clip = one generation = **one line he speaks**. The generator's clip length is the budget
  (Veo 8 s: ≤ 7.8 s of speech, ~2.7 words/s at a calm read → ≤ 20 words; Runway: per profile).
- Split at sentence or clause boundaries. A sentence longer than the budget becomes two clips,
  never a rushed read. Never change the words to fit — flag it to the user instead.
- Lead each clip with ~0.4 s of silence and end with a silent tail: they are the cut points.

### 2. Choose a view and write the prompt

Pick the view template per clip (`templates/prompts/`): `podcast-host`, `podcast-guest`,
`presenter-to-camera`, … Fill its slots (line timed in seconds, delivery, gesture) and render it
with `tools/render-prompt.mjs` conventions for the project's generator. Rules that the templates
already encode (and you must not break):
- **Vanilla clips:** locked-off camera, no zoom, no grade. All framing moves happen in Remotion.
- **Nothing the generator will garble:** no on-screen text, logos, UI, maps with labels, phones
  with readable screens. Every one of those is a Remotion element.
- **Gestures toward the graphics:** where a graphic will appear beside him, direct a gesture
  toward that side of frame on the word that introduces it.
- Spell numbers out ("twenty percent"); brand names as they should be *said* ("Hey Anaya").

### 3. Design every beat (the Remotion plan)

For each clip decide:

**Host layout** — keyframes `[cue, mode]`:

| mode | what the viewer sees | use it when |
|---|---|---|
| `full` | the host, edge to edge (slow `push` creep optional) | the line *is* the person: a hook, a question, a punch line |
| `split` | host in a panel (left in 16:9, top in 9:16), a graphic beside/below him | he is explaining something concrete — the graphic shows it as he says it |
| `pip` | a full-screen graphic, the host in a small ringed circle | the idea is bigger than a panel: a map, a counter, a network, many items |

The host's voice never cuts; only his framing changes. `from` animates a beat in from the
previous beat's mode so layout changes read as camera moves, not edits.

**Scenes** — one or more per beat, each with a layer:
- `under` — full screen beneath the host; fades in as he goes `pip`.
- `beside` — the split panel (16:9: 1060×930u at x 860; 9:16: 1080×1060u at y 860).
- `over` — on top of everything (a logo bug, a strike-through line, a callout).
- Built-in scene: `LogoBug` (cues `in`, `out`). Every other scene is designed for this video.

For each scene write: `name` (PascalCase, unique in the project), `layer`, `idea` (one or two
sentences: what the viewer sees and why), `props` (the copy and data it shows), and `cues`
(named moments, each a word reference — below). The scene-builder implements exactly this.

**Cue references** (resolved against the ingested clip's words by `build-timeline.mjs`):
`2.4` (seconds) · `"multiply"` (first time he says it) · `"leads#2"` (second time) ·
`"deal-0.6"` (0.6 s before the word) · `"@start"` · `"@end-0.5"`.

### 4. Design rules (from the productions so far)

1. **Show, don't restate.** A graphic carries what the words can't: the product working, a
   number growing, a place, a before/after. Kinetic text only for the close and the end card.
2. **Every beat gets a visual change; no two adjacent beats share a layout and scene type.**
   Alternate `full → split → pip`; the face returns at least every other beat.
3. **One idea per visual state.** A new clause with new information changes the graphic; an
   elaboration evolves it (secondary motion), it never resets.
4. **Cue on the word.** An element lands on the start of its word (lead by 1–2 frames); a reveal
   that *answers* a setup lags 0.2–0.5 s. Nothing animates during his breaths.
5. **The product is the hero of the solution beat** — show it doing each thing he names, one
   cue per capability, in the order he says them.
6. **Honest numbers.** Any figure not supplied by the user is labelled "Illustrative" on screen.
7. **Fits both aspects.** Every scene must work in the 16:9 panel and the 9:16 panel/full frame;
   keep full-screen scenes clear of the pip corner (16:9 bottom-left, 9:16 top-right) and of the
   caption band (16:9 bottom 150u; 9:16 around y 640–720).
8. **Reading time.** On-screen text holds `(characters ÷ 12) + 0.5` s after it lands.
9. **Real UI, no trademarks.** WhatsApp-*style* chat (generic green, no logo) is fine; brand
   logos only the client's own.

### 5. Write the files

`storyboard.json` (validates against `schemas/storyboard.schema.json`):
```json
{
  "slug": "heyanaya-script4", "fps": 24, "generator": "veo",
  "brand": { "name": "HeyAnaya", "logo_light": "logo-white.png", "logo_dark": "logo-black.png" },
  "framing": { "face_x": 0.5, "face_y": 0.28, "body_y": 0.4 },
  "captions": { "landscape": true, "vertical": true, "emphasis": { "pos": ["instantly"], "neg": ["unanswered"] } },
  "end_card": { "seconds": 3.2, "headline": "…", "cta": "Book a demo", "url": "" },
  "clips": [
    { "id": "01", "section": "Hook", "view": "podcast-host", "line": "A few unanswered WhatsApp enquiries don't seem like a big deal.",
      "prompt": { "delivery": "…", "gesture": "…" },
      "edit": {
        "host": [["@start", "full"], ["WhatsApp-0.1", "split"]], "push": 0.06, "grade": "cool",
        "scenes": [ { "name": "UnansweredChat", "layer": "beside",
          "idea": "One clinic's phone: a patient asks for a slot; the 'no reply' clock runs.",
          "props": { "clinic": "Clinic 1 · Jumeirah", "message": "Hi! Do you have a slot this week?" },
          "cues": { "message": "enquiries", "alert": "deal-0.6" } } ] } }
  ]
}
```
`storyboard.md` — for the user: a table per clip (line · view · layout · what's on screen, word by
word), then the prompts to paste. Brand logos go in `01_vision/brand/`.

**Gate 🔍** — the user approves `storyboard.md` (`approved.storyboard: true`). Then `stage: generate`.

## ② Generate

The user pastes `03_prompts/clip-NN.prompt.md` into the generator with the cast still as the first
frame and drops the results into `04_clips/` — any file names, extra takes welcome. `stage: ingest`.

## ③ Ingest

```bash
python3 tools/ingest.py <slug>          # --force to redo, --model small.en for speed
```
Read its report. Fix before moving on: a `missing` clip (generate it), similarity < 0.8 (the take
says something else — regenerate, or accept and update the storyboard line), a trim that cuts a
word. Then open two or three `05_ingest/words/NN.json` and sanity-check timings. `stage: scenes`.

## ④ Scenes

**Agent:** `scene-builder` · writes `remotion/src/projects/<slug>/<Scene>.tsx` for every scene in
the storyboard and `index.tsx` exporting `SCENES`, then `node tools/register-scenes.mjs`.
Use the engine's hooks and primitives (`remotion/src/explainer/context.tsx`, `primitives.tsx`):
`useCues()` for timing (never hard-coded seconds), `usePalette()`, `useLayout()` (`u` scaling,
`vertical`), `useGeometry()` for the panel and pip rect, `useBeat()` + `usePipAmount()` when a
full-screen scene must know the host's state. `cd remotion && npx tsc --noEmit` must pass.

## ⑤ Edit + QC

```bash
node tools/build-timeline.mjs <slug>    # resolves every cue; fails on a word that isn't spoken
tools/stills.sh <slug>                  # both aspects → 05_review/stills/sheet_16x9.jpg, sheet_9x16.jpg
```
**Look at both sheets.** Check: nothing clipped by the frame or the panel, text readable at size,
captions not covering a graphic's key element, the pip corner clear, the host's face framed in
`split`/`pip` (tune `framing` in the storyboard if not), both aspects. Fix in the scene code or the
storyboard, rebuild, re-shoot stills. Repeat until clean. Gate 🔍: show the user the sheets.

## ⑥ Render

```bash
tools/render.sh <slug>                  # renders/<slug>_vNN_16x9.mp4 + _9x16.mp4, −14 LUFS / −1 dBTP
tools/render.sh <slug> --speed 1.2      # also a 1.2× variant (pitch kept, 30 fps)
```
Check the output: duration, loudness line printed by `master.sh`, a frame tile across the
timeline. Log the version in `log.md`. The user watches; every note becomes a storyboard or scene
change, a rebuilt timeline (new version), and a new render — never an overwrite.
