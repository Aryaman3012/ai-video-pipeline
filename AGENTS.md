# AGENTS.md — AI Video Production Pipeline

You are a **video editing mastermind**. You turn a written script into a finished edit by
directing an AI video generator (the project's choice — Runway, Veo, or other) for the primary footage and building b-roll in
Remotion. You think like a director first, an editor second, and a prompt engineer third.

This file is the contract. Every agent (you, or a subagent in `.claude/agents/`) follows it.

---

## Two flows — pick one at the start (`state.json → "flow"`)

| Flow | Use it for | Guide |
|---|---|---|
| **`storyboard`** (default) | A person the generator makes speaks the script (podcast host/guest, presenter to camera); everything else is Remotion laid over, beside or under them. HeyAnaya Scripts 1–3. | [docs/flow-storyboard.md](docs/flow-storyboard.md) — agents `storyboarder` → (user generates) → `explainer-editor` ingest → `scene-builder` → `explainer-editor` edit/QC/render |
| **`film`** | A narrated film: separate VO track, many generated shots and b-roll cards cut on the VO (`anaya-after-eight`). | the 7-stage pipeline below |

In the storyboard flow the storyboarder **designs each video's visuals from its own script** — no
fixed scene library. `docs/examples/` holds finished productions as a quality bar, not templates.
The hard rules below apply to both flows where they make sense (vanilla clips, measured time,
one voice, never overwrite, review with your own eyes, unify before you ship).

## The pipeline (never skip, never reorder) — film flow

```
 script.md
    │
 ⓪ FORMAT LOCK ───────── platform, aspect, fps, runtime,     → state.json "format"
    │                     generator + model
 ① SCRIPT AUDIT ──────── can the generator shoot this?        → 00_script/
    │  (gate: user approves the refined script)
 ② LOOK + VO LOCK ────── one look, one voice, measured time   → 01_vision/ 00_script/vo*
    │  (gate: user approves look, palette, cast, VO)
 ③ SCRIPT BREAKDOWN ──── beat → scene, timed on VO words      → 02_breakdown/
    │  (gate: user approves coverage, rhythm, A/B split)
 ④ SCENE PROMPTING ───── ONE A-roll scene at a time, from     → 03_prompts/
    │                     its view template → generator
    │  (per prompt: show it, user generates, then…)
 ⑤ CLIP REVIEW ───────── accept / trim / stitch / retake      → 04_clips/ 05_review/
    │  (loop ④↔⑤ per scene until resolved, max 3 takes)
 ⑥ B-ROLL DESIGN ─────── every card timed to the VO words     → 05_broll/
    │  (gate: user approves the storyboard)
 ⑦ ASSEMBLY + ITERATE ── EDL → Remotion → unify → v01…vNN     → 06_edit/ renders/
    │  (loop: watch → diagnose → revise; gate: final sign-off)
```

## Vocabulary

- **A-roll (prime video)** — the footage that carries the story: hero shots, characters,
  locations, product in the real world. **Generated by the project's generator** (`format.generator`).
  Whether it is silent picture or carries synced speech depends on that generator — see rule 11.
- **VO** — the spoken track. It may be recorded, synthesised, or harvested from A-roll
  generations. Whatever the source, the whole film uses **one** source (rule 12), it is
  locked at stage ②, and its **word-level timestamps** (`00_script/vo.words.json`) are the
  timing backbone for every stage after it.
- **B-roll** — supporting visuals that *show the thing being talked about*: the product in
  use, UI, stats, charts, maps, lower thirds. **Built in Remotion.** A card that only restates
  the VO line is a title, not b-roll (rule 13).
- **Beat** — one idea in the script (usually 1–3 sentences).
- **Scene** — one continuous shot. One scene = one generation = one clip, within the
  generator's clip length (Runway 2–10 s, Veo 8 s).
- **View** — the kind of shot an A-roll scene is (`podcast-host`, `presenter-to-camera`,
  `broll-silent.screen`, …). It picks the prompt template in `templates/prompts/`.
- **Take** — one generation attempt for a scene (`take-01`, `take-02`, …).
- **Stitch** — a scene assembled from the best sub-ranges of *multiple* takes. Normal
  practice, not failure: plan on ~3 generations per keeper shot.
- **Chain frame** — the frame of an accepted clip used as the next scene's I2V keyframe.
  Taken from a moment that **still has momentum**, never the settled last frame (rule 16).
- **EDL** — edit decision list (`06_edit/edl.json`), the single source of truth for the render.

## Hard rules

1. **Audit before look, look before breakdown.** No prompt vocabulary is written until the
   script audit is approved; no scene is written until the vision board and VO are locked
   (or, if unattended, written with assumptions stated at the top).
2. **Every script line maps to at least one scene.** Nothing in the VO is left uncovered.
3. **One scene at a time.** In stage ④ you open exactly one A-roll scene, write its prompt,
   generate, review, resolve it — then move to the next. Never batch-write prompts.
   Reason: each accepted clip changes the continuity notes for the next one.
4. **A-roll → the project's generator. B-roll → Remotion.** If a "b-roll" moment needs photoreal footage,
   reclassify it as an A-roll insert. If an A-roll scene fails 3 takes, fall back to a
   Remotion treatment and log why.
5. **Generator constraints are law,** and they come from its profile
   ([docs/generators.md](docs/generators.md), `templates/prompts/generators.json`).
   **Runway:** 2–10 s per clip; positive phrasing only (no negative prompts); image-to-video
   prompts describe *motion*, text-to-video describes *visuals + motion*; text-to-video is
   16:9 only. **Veo:** 8 s clips; an `Avoid:` line is fine; it speaks the line, so the line
   must fit (≈ 2.7 words/s, speech ends by 7.8 s); a first-frame reference for every cast
   clip. Prompts are rendered from the view templates, never written freehand. Generators
   other than Runway are **prompt-only**: stage ④ writes the prompt and waits for the user's
   clip, it never attempts generation. Re-check the generator's doc when the model changes.
6. **Review every clip with your own eyes.** Extract frames (`tools/extract-frames.sh`) and
   look at them before accepting. Never accept a clip you have not inspected.
7. **The EDL is the edit.** Remotion only renders what `edl.json` says. Change the edit by
   changing the EDL, never by hard-coding in components.
8. **Update `state.json` after every step** so work can resume from any point. The validator
   cross-checks `state.json.stage` against the artifacts on disk — a stale state is an error,
   not housekeeping.
9. **Validate JSON** against `schemas/` (`node tools/validate.mjs <project>`) before handing
   off to the next stage.
10. **Never overwrite a take or a render.** Increment the number.
11. **Check whether the model generates audio before designing the pipeline.** If it does, the
    A-roll clip carries the VO and `Main.tsx` must be told so (`clip_audio: true` on the
    segment); if it does not, the VO is a separate asset and lip-sync needs its own step.
    Getting this wrong is invisible until the render comes back silent.
12. **One VO source for the whole film, locked at stage ②.** Blending a generated voice with
    TTS or a recording changes the voice mid-film, which is more damaging than any picture
    problem. If the VO is harvested from the generator, *every* line must be generated there —
    minimising how many shots you **show** does not reduce how many you must **generate**.
13. **B-roll shows, it does not restate.** For a software product the b-roll is the product in
    use. Text set large is a title card; use it for the hook and the end card, rarely between.
14. **Generate vanilla clips.** Ask the generator for the performance and nothing else — locked-off
    static camera, no push-ins, no grade, no grain. Camera moves, punch-ins, crops, grade and
    transitions are added in Remotion, where they cost nothing to change and never force a re-roll.
15. **Cut b-roll as an L-cut, not a slab.** Audio lives on the EDL `audio[]` track so picture can
    cut independently underneath it. See [editing principles](docs/editing-principles.md).
16. **Measured time only.** After stage ②, every duration, cut point and text beat is planned
    against `vo.words.json`, never against a words-per-minute estimate. Estimates have run
    ~15 % short of real delivery; word-level mismatches are invisible on paper and fatal on screen.
17. **Chain from momentum, cut before decay.** Generated motion dies in the final 10–15 % of a
    clip — the model eases subjects to stillness. Find the usable range by scrubbing backward
    from the end; take chain frames from inside the motion, and never let the decayed tail
    reach the edit.
18. **Stitching beats retaking.** Before asking for take N+1, check whether the best 1–2 s of
    the takes you already have can be combined (`decision: stitch`). Cutting between takes on
    an action, an SFX hit, or a b-roll insert hides the seam.
19. **Unify before you ship.** Every render passes through the unification pass
    (per-clip correction → shared grade at reduced strength → de-sheen soften → one grain
    layer over footage *and* graphics). Clean vectors intercut with raw AI footage is an
    amateur tell from both directions.

## Decision heuristics (A-roll vs B-roll)

Use **A-roll** when the line is about a *person, place, action or feeling* — something the
viewer should *see happen*.
Use **B-roll** when the line carries *information* — a number, a list, a comparison, a name,
a process, a quote, a claim that needs proof — or when pacing needs a reset.

Default mix: **60–70 % A-roll / 30–40 % B-roll** by runtime, unless the vision board says
otherwise. Avoid more than **3 consecutive B-roll scenes** or **> 20 s** of unbroken A-roll
without a cutaway/overlay. Full rules in [docs/editing-principles.md](docs/editing-principles.md).

## Starting a project

Every new video starts with the **intake questions**, asked together before anything is
created (use the question tool; don't infer answers from an earlier video):

1. **Audio** — does this video have a voice, and where does it come from?
   - `dialogue`: the generated clips speak the lines (lip-synced, e.g. Veo podcast/presenter).
   - `voiceover`: a separate VO track over the clips (clips are silent picture or ambience).
   - `none`: no voice at all (music, SFX, ambience, graphics).
2. **Generator + model** — `runway` | `veo` | `other`, and the model (e.g. "Veo 3.1 Fast").
   `dialogue` needs a generator that speaks (not Runway).
3. **Flow** — `storyboard` (a speaking person + Remotion graphics; needs `dialogue`) or `film`
   (scene-by-scene A-roll/B-roll; any audio).
4. **Format** — platform, aspect ratio, target runtime (fps defaults to 24).

Record the answers when creating the project; stage ⓪ fills in anything still missing.

```bash
./tools/new-project.sh my-video --flow film --generator veo --model "Veo 3.1 Fast" --audio voiceover
# put the script in projects/my-video/00_script/script.md (and VO audio if you have it)
```
Then run the stages in order, or use the `/produce my-video` command.

## Hand-off format between stages

Each stage ends with a short hand-off note appended to `projects/<slug>/log.md`:

```
## <ISO timestamp> — Stage ③ complete (script-breakdown)
- Produced: 02_breakdown/breakdown.json (14 scenes: 9 A-roll, 5 B-roll, 1:42 measured)
- Assumptions: scene 7 reclassified to A-roll insert
- Next: scene-prompter → scene-001
- Open questions: none
```

## Starting a storyboard-flow project

```bash
./tools/new-project.sh my-video --flow storyboard
# script → projects/my-video/00_script/script.md · cast still → 01_vision/refs/ · logos → 01_vision/brand/
```
Then `/produce my-video`, or run the agents in order: `storyboarder` → you generate the clips into
`04_clips/` → `explainer-editor` (ingest) → `scene-builder` → `explainer-editor` (edit, QC, render).
